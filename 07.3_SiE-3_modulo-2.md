## 1. Propósito y Alcance

**Propósito:** Gestionar el ciclo de vida completo de la oferta académica de la Universidad Autónoma Metropolitana, desde la creación de una Unidad de Enseñanza-Aprendizaje (UEA) hasta la supresión de un plan de estudios, garantizando el cumplimiento estricto del **Reglamento de Estudios Superiores (RESUAM)**, particularmente su Capítulo VI, y gestionando las interdependencias entre planes de estudio de todas las divisiones, unidades e instituciones participantes.

**Alcance Normativo:**
*   **RESUAM:** Capítulo VI (Planes y Programas de Estudio, Art. 33-57)
*   **AGA:** Variables 3, 4, 5, 6, 7, 10, 11, 24, 47, 49, 50, 51
*   **Estados del Plan:** VIGENTE, EN_CONVERSION, CONVERTIDO, SUPRIMIDO
*   **Calendario Escolar:** 3 trimestres lectivos (Otoño, Invierno, Primavera)

**Alcance Institucional:** Todas las divisiones y unidades de la UAM:
*   **Unidad Iztapalapa:** CBI, CBS, CSH
*   **Unidad Cuajimalpa:** CCD
*   **Unidad Azcapotzalco:** AZC
*   **Unidad Xochimilco:** XOC
*   **Unidad Lerma:** LER

**Nota de Delimitación:** Este módulo se enfoca exclusivamente en las reglas de negocio para el **alta, adecuación, modificación y conversión de planes de estudio** y **gestión de UEAs**. **Sólo puede haber un plan de estudio activo por clave de plan**. Las reglas operativas de cumplimiento del plan (plazos máximos, oportunidades de evaluación, etc.) se gestionan en los Módulos 6 (Programación Escolar), 7 (Evaluación), 8 (Kardex) y 9 (Servicios Escolares).

**Nota de Corrección Estructural:** 
*   **Validar actas firmadas:** La calificación y firma de actas se maneja en el **Módulo 7 (Evaluación)**, no en este módulo. Un profesor que imparte una UEA opera como sinodal para la firma de actas.
*   **Simulación de inconsistencias:** La simulación debe reportar inconsistencias en las reglas de conversión autorizadas antes de ejecutar la conversión.
*   **Modificación vs. Adecuación:** Son **procedimientos separados** regulados por legislación diferente (Art. 49 vs Art. 51 RESUAM), con órganos aprobadores distintos (Colegio Académico vs Consejo Divisional).

## 2. Análisis de Interdependencia entre Planes de Estudio

Basado en el análisis de **60+ programas académicos** (26 licenciaturas, 4 especializaciones, 15 maestrías, 15 doctorados) de la UAM, se identifican las siguientes interdependencias estructurales:

### 2.1. Principio de Plan Único Activo

```
┌─────────────────────────────────────────────────────────────────────────────────┐
│                    PRINCIPIO DE PLAN ÚNICO ACTIVO - UAM                         │
├─────────────────────────────────────────────────────────────────────────────────┤
│                                                                                 │
│  REGLA FUNDAMENTAL:                                                             │
│  ┌─────────────────────────────────────────────────────────────────┐            │
│  │  Por cada clave de plan (ej. 30, 51, 112), SÓLO puede haber     │            │
│  │  UN plan VIGENTE a la vez. No hay planes concurrentes.          │            │
│  └─────────────────────────────────────────────────────────────────┘            │
│                                                                                 │
│  TRANSICIÓN DE VERSIONES:                                                       │
│  ┌─────────────────┐      ┌─────────────────┐      ┌─────────────────┐          │
│  │  Versión N      │────▶│  EN_CONVERSION  │────▶│  Versión N+1    │          │
│  │  (VIGENTE)      │      │  (Transición)   │      │  (VIGENTE)      │          │
│  │  Activa         │      │  Simulación +   │      │  Activa         │          │
│  │                 │      │  Conversión     │      │                 │          │
│  └─────────────────┘      └─────────────────┘      └─────────────────┘          │
│                                                                                 │
│  REVERSA EN KARDEX (Módulo 8):                                                  │
│  ┌─────────────────────────────────────────────────────────────────┐            │
│  │  La reversa NO es de la versión del plan, sino de la            │            │
│  │  APLICACIÓN DE REGLAS DE CONVERSIÓN en el historial             │            │
│  │  académico de cada alumno (Módulo 8: Kardex).                   │            │
│  │                                                                 │            │
│  │  - Reversa Total: Todos los alumnos convertidos                 │            │
│  │  - Reversa Parcial: Alumnos específicos con errores             │            │
│  │  - Permite afinar reglas de conversión                          │            │
│  └─────────────────────────────────────────────────────────────────┘            │
│                                                                                 │
│  PRERREQUISITO DE CONVERSIÓN:                                                   │
│  ┌─────────────────────────────────────────────────────────────────┐            │
│  │  Debe haber AL MENOS UN alumno:                                 │            │
│  │  1. Activo en el plan, O                                        │            │
│  │  2. Que pueda recuperar su calidad de alumno                    │            │
│  │  → Sin alumnos, no hay conversión                               │            │
│  └─────────────────────────────────────────────────────────────────┘            │
│                                                                                 │
└─────────────────────────────────────────────────────────────────────────────────┘
```

> **Explicación didáctica:** A diferencia de otros sistemas universitarios, la UAM maneja **un solo plan activo por clave de plan**. Cuando se aprueba una nueva versión, el plan anterior deja de ser vigente. La **conversión** es el proceso que migra a los alumnos activos del plan anterior al nuevo plan. Este proceso tiene **dos fases** (simulación y conversión) y requiere al menos **un alumno activo** o que pueda recuperar su calidad. **CORRECCIÓN ESTRUCTURAL:** No hay reversa de la transición de versiones del plan. Una vez que la versión N+1 es VIGENTE, no hay vuelta atrás a la versión N. La **reversa ocurre en el Módulo 8 (Kardex)** en la **aplicación de las reglas de conversión** en el historial académico de cada alumno. Esto permite afinar reglas que no funcionen correctamente durante la conversión sin revertir la versión del plan.

### 2.2. Separación entre Modificación y Adecuación

| Característica | Modificación (Art. 49) | Adecuación (Art. 51) |
|---------------|----------------------|---------------------|
| **Tipo de cambio** | Sustantivo (afecta concepción del plan) | Menor (no afecta concepción) |
| **Ejemplos** | Cambios en objetivos, estructura, créditos totales | Cambios en nombre, seriación, bibliografía, actualización de contenidos |
| **Órgano aprobador** | Colegio Académico | Consejo Divisional |
| **Plazo de vigencia** | Inmediato (según acuerdo) | Al menos 1 trimestre lectivo después de aprobada |
| **Procedimiento** | Completo (34-40 RESUAM) | Simplificado (51 RESUAM) |
| **Estados del plan** | EN_MODIFICACIÓN | EN_ADECUACIÓN |

> **Explicación didáctica:** Aunque ambos son cambios al plan de estudios, **modificación y adecuación son procedimientos separados** regulados por artículos diferentes del RESUAM. La **modificación** (Art. 49) requiere aprobación del **Colegio Académico** porque afecta la concepción del plan. La **adecuación** (Art. 51) es aprobada por el **Consejo Divisional** porque son cambios menores. El sistema debe manejar estos como **flujos separados** con estados, validaciones y órganos aprobadores distintos.

> **Explicación didáctica:** La **clave UEA** es un identificador crítico que debe ser único en toda la universidad. Los primeros 2 dígitos identifican la división y unidad (21=CBI Iztapalapa, 52=CBS Iztapalapa, 40=CSH Iztapalapa). Los siguientes 2 dígitos identifican el área de conocimiento dentro de la división. Los últimos 3 dígitos son un consecutivo único. La **estructura de UEA es flexible** para acomodar la variabilidad observada en los planes de estudio: modalidades de evaluación configurables, factores de ponderación a juicio del profesorado, seriaciones múltiples. El sistema debe permitir esta flexibilidad manteniendo validaciones críticas (suma de ponderaciones = 100%, sin ciclos de seriación).

> **Explicación didáctica:** Un plan de estudio tiene **estados de ciclo de vida** que incluyen la transición de conversión. La **regla fundamental** es que **sólo puede haber un plan vigente por clave de plan**. No hay planes concurrentes. **CORRECCIÓN CRÍTICA:** **Modificación y Adecuación son procedimientos separados** con estados distintos (EN_MODIFICACIÓN vs EN_ADECUACIÓN), órganos aprobadores diferentes (Colegio Académico vs Consejo Divisional) y regulaciones distintas (Art. 49 vs Art. 51 RESUAM). Cuando se aprueba una nueva versión: (1) la versión N pasa a EN_CONVERSION, (2) la versión N+1 pasa a VIGENTE, (3) después de la conversión, la versión N pasa a CONVERTIDO. Las **adecuaciones** (Art. 51) son cambios menores que no requieren Colegio Académico, pero deben informarse dentro de los 5 días hábiles siguientes y entran en vigor al menos 1 trimestre después. El **versionamiento** es crítico: planes como 112_4 y 112_5 (Matemáticas) o 51_9 (Ciencias Antropológicas con 3 niveles) son versiones secuenciales, no concurrentes.

El **prerrequisito fundamental** es que debe haber **al menos un alumno activo** o que pueda recuperar su calidad de alumno. Sin alumnos, no tiene sentido ejecutar la conversión y el sistema debe bloquearla. El **prerrequisito operativo** es que todas las UEA del trimestre en curso deben tener **actas firmadas por sinodales**. **CORRECCIÓN:** La validación de actas firmadas se maneja en el **Módulo 7 (Evaluación)**, donde un profesor que imparte una UEA opera como sinodal. El proceso tiene **dos fases**: (1) **SIMULACIÓN** que estima impactos sin modificar kardex y **reporta inconsistencias en las reglas de conversión autorizadas**, y (2) **CONVERSIÓN** que transforma realmente la historia académica. **CORRECCIÓN ESTRUCTURAL CRÍTICA:** No hay reversa de la versión del plan. Una vez que version_destino es VIGENTE, no hay vuelta atrás a version_origen. La **reversa ocurre en el Módulo 8 (Kardex)** en la **aplicación de las reglas de conversión** en el historial académico de cada alumno. Esto permite **REVERSA TOTAL** (todos los alumnos) o **REVERSA PARCIAL** (alumnos específicos) para afinar reglas que no funcionen correctamente, **sin revertir la versión del plan**. La conversión debe realizarse con **trazabilidad completa** en el **siguiente trimestre**.

### 6.3 Estados del Ciclo de Vida

**PlanEstudio:**
*   `Borrador` → `En_Revision_Divisional` → `En_Dictamen_Academico` → `En_Analisis_Colegio` → `Aprobado_Pendiente` → `VIGENTE` → `EN_MODIFICACIÓN` / `EN_ADECUACIÓN` → `EN_CONVERSION` → `CONVERTIDO` → `Suprimido`
*   **NOTA:** **Modificación y Adecuación son estados separados** con órganos aprobadores distintos. No hay estado de reversa de versión. Una vez `CONVERTIDO`, no hay vuelta atrás a `VIGENTE`.

**UEA:**
*   `Propuesta` → `En_Validacion` → `Aprobada` → `Vigente` → `En_Modificacion` → `Baja`

**ExpedientePlan:**
*   `En_Elaboracion` → `En_Revision` → `Completado` → `Archivado`

**TablaEquivalencia:**
*   `En_Generacion` → `En_Validacion` → `Prerrequisito_Verificado` (alumnos activos + **actas firmadas Módulo 7**) → `Simulacion` (**reporta inconsistencias**) → `Conversion` → `Completada`

**ConversionBitacora:**
*   `Simulacion_Iniciada` → `Simulacion_Completada` (**inconsistencias_reportadas**) → `Conversion_Iniciada` → `Conversion_Completada` → `Reversa_en_Kardex` (si aplica, en Módulo 8)

**AlumnoPlan:**
*   `Activo` → `En_Conversion` → `Convertido` → `Revertido_en_Kardex` (si aplica, en Módulo 8)

## 10. Conclusión del Módulo 2

El **Módulo 2: Planes y Programas de Estudio** constituye el **núcleo estructural** del Sistema de Información Escolar y establece las bases para toda la operación académica de la Universidad. Sus características distintivas son:

1.  **Enfoque en estructura normativa:** Este módulo gestiona exclusivamente el **alta, adecuación, modificación, supresión y conversión de planes de estudio** y **gestión de UEAs**. Las reglas operativas de cumplimiento se gestionan en los Módulos 6, 7, 8 y 9.

2.  **Principio de plan único activo:** **Sólo puede haber un plan vigente por clave de plan**. No hay planes concurrentes. Cuando se aprueba una nueva versión, la versión anterior pasa a EN_CONVERSION y luego a CONVERTIDO.

3.  **Modificación y Adecuación son procedimientos separados:** **CORRECCIÓN CRÍTICA:** Modificación (Art. 49) y Adecuación (Art. 51) son **procedimientos separados** con estados distintos (EN_MODIFICACIÓN vs EN_ADECUACIÓN), órganos aprobadores diferentes (Colegio Académico vs Consejo Divisional) y regulaciones distintas.

4.  **Conversión en dos fases:** El proceso de conversión tiene **dos fases obligatorias**: (1) **SIMULACIÓN** que estima impactos sin modificar kardex y **reporta inconsistencias en las reglas de conversión autorizadas**, y (2) **CONVERSIÓN** que transforma realmente la historia académica de cada alumno.

5.  **Prerrequisito de alumnos:** La conversión **requiere al menos un alumno activo** o que pueda recuperar su calidad de alumno. Sin alumnos, no tiene sentido ejecutar la conversión y el sistema debe bloquearla.

6.  **Prerrequisito de actas firmadas:** Todas las UEA del trimestre en curso deben tener **actas firmadas por sinodales**. **CORRECCIÓN:** Esto se valida en el **Módulo 7 (Evaluación)**, donde un profesor que imparte una UEA opera como sinodal para la firma de actas.

7.  **CORRECCIÓN ESTRUCTURAL CRÍTICA - Reversa en Kardex:** **No hay reversa de la versión del plan**. Una vez que version_destino es VIGENTE, no hay vuelta atrás a version_origen. La **reversa ocurre en el Módulo 8 (Kardex)** en la **aplicación de las reglas de conversión** en el historial académico de cada alumno. Esto permite **REVERSA TOTAL** (todos los alumnos) o **REVERSA PARCIAL** (alumnos específicos) para afinar reglas que no funcionen correctamente, **sin revertir la versión del plan**.

8.  **Simulación reporta inconsistencias:** **CORRECCIÓN:** La simulación debe **reportar inconsistencias en las reglas de conversión autorizadas** antes de ejecutar la conversión, permitiendo ajustar reglas problemáticas.

9.  **Gestión de interdependencias:** El sistema maneja UEA compartidas entre divisiones (CBI, CBS, CSH), unidades (AZC, IZT, XOC, CUA, LER) e instituciones, permitiendo movilidad académica interna y externa con trazabilidad completa.

10. **Expediente documental completo:** Cada plan tiene un historial documental que garantiza transparencia y auditoría, incluyendo observaciones técnicas y legales atendidas, comisiones de posgrado, LGAC, **bitácora de conversiones con reglas aplicadas** e **inconsistencias reportadas en simulación** (para permitir reversa en Módulo 8 si es necesario).

11. **Versionamiento secuencial:** El sistema maneja versiones secuenciales de planes (ej. 112_4 → 112_5 Matemáticas, 51_9 con 3 niveles integrados) con tablas de equivalencias y trazabilidad de transiciones. **No hay versiones concurrentes ni reversa de versión**.

12. **Estructura flexible de UEA:** El sistema soporta la **gran variabilidad y flexibilidad** de los planes de estudio en la UAM: modalidades de evaluación configurables, factores de ponderación a juicio del profesorado, seriaciones múltiples, créditos variables.

13. **Delimitación clara de responsabilidades:** Este módulo se enfoca en la **estructura del plan**, mientras que:
    *   **Módulo 6 (Programación Escolar):** Reglas de operación trimestral
    *   **Módulo 7 (Evaluación):** Calificación y **firma de actas**, profesor = sinodal
    *   **Módulo 8 (Kardex):** Reglas de cumplimiento del plan por alumno, **ejecución de conversión, reversa de aplicación de reglas**, inconsistencias de simulación
    *   **Módulo 9 (Servicios Escolares):** Reglas de trámites y excepciones

Este módulo sienta las bases para los módulos subsiguientes, particularmente el **Módulo 6 (Programación Escolar)** que utilizará el catálogo de UEA vigentes para ofertar grupos trimestrales, el **Módulo 7 (Evaluación)** que gestionará la calificación y firma de actas, y el **Módulo 8 (Kardex)** que ejecutará las conversiones de plan en el historial académico de los alumnos con trazabilidad completa y **capacidad de reversa de aplicación de reglas** (no de versión del plan).

> **Nota metodológica:** Este documento es parte de un ejercicio académico de modelado funcional que demuestra la adaptación de un Sistema de Información Empresarial a un dominio específico (escolar) utilizando una organización pública concreta como estudio de caso. Las especificaciones presentadas tienen fines ilustrativos y pedagógicos, y no sustituyen la consulta directa de los ordenamientos oficiales ni la asesoría de las instancias competentes de la Universidad Autónoma Metropolitana o cualquier otra institución.

> **Advertencia de uso:** La información contenida en este documento está basada en documentación pública disponible hasta julio de 2025. Para efectos de implementación real, se requiere validación con las instancias correspondientes y consideración de actualizaciones normativas posteriores.

## Consideraciones para el Modelado UML del Módulo 2

1.  **Clase `PlanEstudio`:** Debe incluir atributos `estado_plan` (VIGENTE, EN_MODIFICACIÓN, EN_ADECUACIÓN, etc.) y `tipo_cambio` (MODIFICACIÓN/ADECUACIÓN). Relación 1:N con UEA, AreaConcentracion, LGAC.

2.  **Clase `UEA`:** Debe ser flexible con `modalidades_evaluacion` (lista configurable) y `factores_ponderacion` (validación suma 100%). Relación N:M consigo misma a través de Seriacion.

3.  **Clase `TablaEquivalencia`:** Debe usar `version_origen` y `version_destino` (no plan_origen/plan_destino). Incluir `actas_firmadas` como prerrequisito validado.

4.  **Clase `ConversionBitacora`:** Debe incluir `inconsistencias_reportadas` de la simulación y `reversa_en_kardex` (si aplica, en Módulo 8).

5.  **Clase `ExpedientePlan`:** Debe incluir `tipo_cambio` (Modificación Art. 49 o Adecuación Art. 51) y `inconsistencias_simulacion`.

6.  **Relación con Módulo 7:** Validación de `actas_firmadas` ocurre en Módulo 7 (Evaluación), donde profesor = sinodal.

7.  **Relación con Módulo 8:** Reversa de aplicación de reglas ocurre en Módulo 8 (Kardex), no en Módulo 2. Módulo 2 solo gestiona estructura del plan.
